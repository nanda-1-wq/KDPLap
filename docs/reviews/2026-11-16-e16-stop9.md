**Offline** (`js/cover/offline.js`, design 73b, R15)
- `offline` and `online` events. The amber bar uses design 73b's words. The footer reads "Offline · kept on this device" (warning color, with an icon) as soon as the connection goes.
- Changes are kept on this device: localStorage, one key per user and book, holding the design + fmt + `last_remap` + the rev it was based on.
  - The autosave makes **no network call** while offline. The new saver state `offline` is not `failed`, so there is no red bar.
  - Nothing is "pending" once a change is kept, so there is no "Leave site?" warning.
- Back online: the design saves, then the kept copy is cleared (only after a save returned a rev).
  - Leaving 09 while offline keeps the saver reachable, and it saves when the connection is back. The saver reads `navigator.onLine` itself.
  - A save that was out when the connection went ends as offline (kept), not as Not saved.
- Next open (R15, **the newest rev wins**):
  - The copy's base rev is equal to the row's rev, or later: the copy is newer. It opens and saves, and the row as it was becomes the visit snapshot.
  - The row's rev is higher: the row was saved after the copy, so the row opens. The copy is written into the history first (reason `visit`) and only then cleared. If that snapshot fails, the copy stays.
- Blocked while offline, with no call made:
  - Write with AI: "You are offline. Writing with AI needs a connection."
  - Pixabay or Unsplash search and pick: "You are offline. Pixabay and Unsplash need a connection." Try again searches once the connection is back.
  - Export is Part 10; its words are ready: "You are offline. Export needs a connection."
- Storage full or blocked: no crash. The footer reads "Offline · not kept: this browser’s storage is full", the change stays pending (the "Leave site?" warning stays on), and the narrow notice does not say kept.
