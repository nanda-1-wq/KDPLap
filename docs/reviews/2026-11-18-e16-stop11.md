### A security note from the automated push review (not changed by this merge)
- **What it says:** the `stock` function checks the per-user limits (30 searches and 10 picks a minute) and the Unsplash hourly budget, and then writes the `stock_calls` row, as two separate steps. So many requests sent at the same moment could all pass the check before any of them is counted.
- **The impact:** a signed-in user could go over their own per-minute limit, or use more of the shared Unsplash budget, but only with parallel requests. The app itself sends one search at a time.
- **The fix:** check and count in one locked database step, a function with an advisory lock per user. That needs a migration and a stock deploy.
- **Recommendation:** fold it into E16.2 (stock v2), on the owner's word.
