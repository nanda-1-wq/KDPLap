## Part B · Export: proposals (points 1 to 7)

**1. Which text.** Each section's `current_version_id`, in chapter `position` then section
`position` order. Unsaved drafts (`section_drafts`) are never exported.
- No text (no version, or blank content): left out. A chapter with no text at all is left out with its heading. Listed in the dialog ("3 sections have no text").
- Not Final: "Include" choice, default **All sections with text**, other option **Final only**. Counts per status shown.
- Also listed as warnings (never blocking): Needs review, current version is `partial` (stopped draft), a draft newer than the saved version ("Export uses its last saved version"), a section being written now (locked state).

**2. Verify marks. Recommend: warn, never block, with a required tick.**
- Count every `[Verify: no source]` in the exported text, plus code-check "number" rows (claim numbers with no source and no mark, same rule as `js/text-checks.js`).
- Warning lists each section (e.g. "2.1 Shoulder rolls · 2 marks") as a link to 06 Write on that section.
- Export button stays off until the tick "Export with 3 open marks. I will check them." is set. With 0 marks there is no tick.
- In the file: marks are removed, the sentence stays. Removal handles marks anywhere (old v15 cases mid-word or after "1."), then fixes double spaces.
- Other app-only marks stripped or converted: Markdown escapes (`\*`, `\- `, `1\. `), the section numbers (4.1) are app labels only, never printed. Kept findings and check results never go in the file.

**3. Book parts (Include, each a 44 px checkbox row):**
- Title page: title, subtitle, pen name (book row + pen name). On.
- Copyright page: on. Fixed text (owner, 2026-10-25; year = the export year, name = the pen name): "Copyright © 2026 Nora Hale. All rights reserved. No part of this book may be reproduced without written permission from the author, except for short quotes in reviews. The information in this book is for general education only. It is not medical, legal or financial advice. Talk to a qualified professional before you start any new exercise or health practice." Edit it in Word.
- Contents: linked list of chapter headings (bookmarks + internal links, no page numbers; works in Word, Google Docs and Kindle). On.
- Introduction / Conclusion: the `kind = intro / conclusion` chapters. Shown only if they exist; on.
- About the author: the pen name's bio (`bio_text`). Shown only if a bio exists; off by default.
- Chapters: always in.

**4. Layout.**
- DOCX: page size from the Brief `trim_size` (5x8 to 8.5x11), mirrored margins (inside 0.875 in, outside 0.625 in, top/bottom 0.75 in), body Georgia 11 pt, 1.15 line spacing, first-line indent 0.25 in (none after a heading). Styles: Title, Subtitle, Heading 1 = chapter ("Chapter 3" + title; intro/conclusion unnumbered), Heading 2 = section title, Heading 3 = "## " inside text. Page break before every Heading 1 and each front-matter page. Real Word lists, bold, italic. Page numbers centered in the footer, starting at 1 on the first chapter (Introduction, or Chapter 1 when there is no Introduction); front matter (title page, copyright, contents) has no page numbers (its own Word section with an empty footer). No running headers. Contents stays a linked list with no page numbers in v1. Full print layout is v2 Print PDF.
- Markdown: one `.md`, same order and same parts: `# Title`, subtitle, "by Pen Name", `#` chapter, `##` section, `###` inner headings. Same mark stripping.
- File name: slug of the title, e.g. `chair-yoga-for-seniors-over-60.docx`.

**5. Where the file is built. Recommend: in the browser.**
| | Browser (docx UMD from jsdelivr, exact version + SRI) | Edge Function |
|---|---|---|
| Fits CLAUDE.md §3 | Yes ("DOCX generated in the browser") | Changes the stack |
| Data access | Same RLS reads the app already does | Service code + new endpoint to validate |
| Cost / deploy | None | Owner deploy, cold starts, body limits |
| Risk | ~400 KB library, loaded only when the dialog opens; CDN can fail → error with retry | Server timeouts on long books |
Markdown needs no library. Exact docx version picked and checked with context7 at build time; local cache in `tests/browser/.cache` like supabase-js.

**6. "DOCX exported" badge.** New insert-only table `book_exports` (user_id, book_id, format, content_key, parts jsonb, created_at; RLS own rows). Written after the file is handed to the browser download.
- `content_key` = hash of title, subtitle, pen name, trim, chosen parts and the ordered list of (section_id, current_version_id) exported. One key function in a new `js/export-key.js`, same pattern as `js/outline-key.js`.
- Books card: "DOCX exported" badge + "Exported Oct 25" in the meta line. Stale when today's key differs: badge "Changed since export" (info icon, gray, not a warning color). Markdown exports are recorded but do not drive the badge.

**7. KDP AI disclosure (advice only).** A short gray note with: "AI first draft: 9 of 12 sections (78% of words) · AI edits only: 2 · Your own text: 1". Rule: a section counts as "AI first draft" when its history has a `generate` version; "AI edits only" when it has improve/expand/shorten/humanize/custom but no generate. Note text: "KDP asks if your book has AI-generated content. Text an AI wrote counts, even after your edits. AI edits of your own text count as AI-assisted, which KDP does not ask about. This is a help, not legal advice." Link "KDP content guidelines". KDP wording rechecked at build time.

**Entry points:** "Export" button in the book header (design 22 position) on every step, and "Export" in the Books card ⋯ menu.

## Part C · Settings: proposals

**1. Account and defaults**
- **Name** field, 1 to 60 characters after trim, saved in a new column `user_settings.display_name` (check constraint; empty saves null = use the fallback). Autosave with the app's Saving / Saved / error pattern. Help: "Shown in the sidebar. Leave empty to use your Google name."
- Name used everywhere (sidebar, avatar letter): `display_name` → `user_metadata.full_name` or `.name` (Google; email sign-up's "Full name" is the same field) → "Your account". Avatar letter = first letter of that name ("Y" for "Your account"). Avatar in ink, not navy.
- Email: shown read-only on the Settings page only (never in the sidebar).
- **Default pen name**: select with "None" + each pen name, same field as the Pen Names "Default" chip; link "Manage pen names".
- **Default trim size**: 5x8, 5.5x8.5, 6x9, 7x10, 8.5x11 (same list as the Brief). Help: "Used for new books. Change a book's size in its Brief."
- Password: "Change password" opens the existing reset email flow; hidden for Google-only accounts. Log out.
- Delete account: left out of v1 (S6).

**2. AI usage this month**
- Tokens used of the limit ("412,380 of 2,000,000 tokens"), percent, bar, "Resets November 1 (UTC)".
- Cost estimate: "About $1.90 so far" at Sonnet 5.5 prices ($2 in / $10 out per million, one price table in the browser, labelled estimate; unknown model shows "no estimate").
- By stage this month: plain names (Write section, Improve, AI check, Outline ideas, Title ideas, Positioning help, Drift check, Brief help, Review insights, Amazon import, Competitor import, Pen name bio), calls, tokens, share bar.
- Last 10 calls: time, stage, book title, tokens, "Not counted" tag for failed / server-stopped calls.
- Data: a new SECURITY INVOKER RPC (sum by stage, counted only, from the 1st UTC) so the 1,000-row cap is gone; last calls = plain `ai_usage` select, own rows by RLS.
- Warning state at 80% and over (Settings only): warning alert with icon + word. At 100%: "AI is paused until November 1. Your writing is safe."

**3. Read-only:** monthly limit (server-set, guarded by 0012), reset date, token numbers, email, language "English".
