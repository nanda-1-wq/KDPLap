## Migration 0025_export_settings.sql (STOP 2)
Header notes the read-only pre-check: last migration 0024, 21 public tables, no book_exports, no display_name.

1. **`user_settings.display_name`** text null. Check: null, or 1 to 60 characters and equal to its own `btrim` (the browser trims). The update policy already allows own rows; the 0012 guard on `monthly_token_limit` is unchanged.
2. **`book_exports`** table:
   | column | rule |
   |---|---|
   | id | uuid pk |
   | user_id | not null, default auth.uid(), → auth.users cascade |
   | book_id | not null, → books cascade |
   | format | 'docx' \| 'md' |
   | include | 'all' \| 'final' |
   | parts | jsonb object: title, copyright, contents, intro, conclusion, about (booleans only) |
   | versions | uuid[]: the exported version ids in book order, 1 to 2,000 |
   | snapshot | jsonb, filled by the trigger only |
   | created_at | default now() |
   - RLS: select and insert own rows. Insert also needs the book to be the user's. No update policy. `update, truncate` are revoked; delete happens only by cascade.
   - Guard trigger (before insert, `search_path = ''`):
     - Every id in `versions` must be a version of a section of this book, owned by the user (P0001 `export_version_not_in_book`).
     - `snapshot` is set from the database: title, subtitle, pen name, `trim_size`, md5 of the pen name bio, the include setting and the parts. Any snapshot the browser sends is overwritten.
     - Only the newest 20 exports per book are kept; older rows are deleted in the same trigger.
   - Index on (book_id, created_at desc) and on user_id. Comments; execute on the trigger function revoked.
3. **`export_json(p_book_id uuid)`** (SECURITY INVOKER, stable). Returns JSON:
   - **book**: title, subtitle, pen name, `bio_text`, `trim_size`.
   - **known**: the Brief and Research fields that `kdpTextChecks.knownOf` reads.
   - **chapters** in order: id, kind, title, needs_review.
     Sections in order: id, title, status, needs_review, the current version (id, version_no, content, partial, word_count) or null, `ai` ('draft' when the history has a generate version, else 'edits' when it has improve/expand/shorten/humanize/custom, else 'none'), `unsaved` (a draft exists and differs from the version), and the run (`started_at`, `heartbeat_at` when state is running).
   - **now**: the server time, so run freshness uses the 0020 rule (heartbeat under 20 s, started under 160 s ago) without trusting the browser clock.
   - Returns null for a book that is not the user's.
4. **`export_badges()`** (SECURITY INVOKER, stable). One row per book that has a DOCX export: `book_id`, `exported_at`, `changed`.
   `changed` is true when any of these differs from the snapshot:
   - title, subtitle, pen name or trim size;
   - the bio, when About the author was in the file;
   - the ordered list of today's current versions of the sections that would be included under the stored include setting and parts. Included means: the section has text (non-blank content), it is Final when include = final, and its chapter is not an intro or conclusion turned off.
5. **`usage_month()`** (SECURITY INVOKER, stable). JSON with `month_start` (the 1st, 00:00 UTC, as the server's `monthStartUtc`), `limit`, `tokens` (counted only), and `by_stage`: [{ stage, model, calls, input, output }]. It sums on the server, so the 1,000-row cap is gone (S10). New index `ai_usage (user_id, created_at)`.
6. Execute on the three functions is revoked from public and anon and granted to authenticated.
