## 4. The export order (the same as the built Print PDF)
Both files go **flush → unsaved check → load → blocked check → build → check → record → download** (`js/format-export.js`):

| Step | Print PDF | EPUB |
|---|---|---|
| flush | :221 | :302 |
| unsaved settings | :223 | :304 |
| load (format_json + export_json) | :224 | :305 |
| blocked | :228 (`blocked()`: trim, nothing Final) | :311 (`model.empty`; any trim works) |
| build | :239 (`engine().build`) | :318 (`kdpEpub.make`, no engine) |
| check | :254 (`kdpPdfCheck`) | :325 (`kdpEpubCheck.read` + `checks` with `domWellFormed`) |
| record | :267 (`recordPdfExport`) | :337 (`recordEpubExport`) |
| stale refusal, no download | :270 | :340 |
| download | :274 | :344 |

Why record before download: the guard (0034 `book_exports_guard`) decides stale against `epub_key` under the book row
lock. Recording first means a stale book downloads nothing, and any other failed record still downloads with the 42b
row "Your EPUB downloaded, but it was not recorded." Tested by mutation 1 (section 8).

## 10. Choices the plan does not cover
1. **The EPUB row while the book is read:** the head and a disabled Export (the Print PDF row carries "Reading the
   book…" or the read error with Try again, as before).
2. **A read failure during an EPUB export** shows in the EPUB row only; the Print PDF row waits (one error, not two).
3. **The never exported Export is secondary** (42b draws an outline button); the Print PDF's first Export stays primary.
4. **Steps:** one step line at a time, as the Print PDF row (section 3, difference 8). The download follows the save at
   once, so it has no step of its own.
5. **Try again after a failed record** sends the same record again (no rebuild, no second file), as the Print PDF.
6. **The `paint()` wait** before the build and the check is `setTimeout(0)` (not `requestAnimationFrame`, which stops in
   a hidden tab), so the step shows before the main-thread work.
7. **A Cancel during the record:** the record may still land (as the Print PDF); nothing downloads.
8. **"Exported <date>" on the Books card** compares dates as times (`new Date`), not as strings, so the three sources'
   formats never matter.
9. **No 08 refresh after an EPUB** (Q4): the 08 header, rail and sidebar never change for an EPUB.
10. **Blob counts in tests:** `window.__blobs` is pushed once per stacked init script in a reused browser, and the
    print preview makes PDF blobs too; the EPUB tests count EPUB blobs and compare "more" or "the same".
