## E10.1 Editor, drafts and versions (no AI)

### Migration 0018_write_versions.sql (file only)

1. **`section_versions` closed to direct inserts.** Same mechanism as 0006, 0010 and
   0017: a BEFORE INSERT guard refuses any insert unless the transaction-local setting
   `kdp.version_write` is `on` (set only inside the RPCs; `set_config` is not exposed
   through the API) or the caller is the service role (generate, E10.2). Through the
   setting only `manual` and `restore` pass. The INSERT grant and policy stay, because
   the RPCs are SECURITY INVOKER and run as the user: a revoke would break them. The guard
   also keeps `user_id` equal to the section's owner (the service role bypasses RLS).
   Update and delete: no policy, and revoked from anon and authenticated.
2. **Text limit** 100,000 characters. `word_count` is set by a trigger from
   `public.md_word_count(content)` (one source of truth; the browser value is ignored).
3. **`section_drafts`** as answer 2. `saved_at` from the server clock (trigger). Owner
   guard: `user_id` = the section's owner; `base_version_id` null or a version of the same
   section.
4. **`sections.current_version_id`** changes only inside the RPCs or by the service role,
   and must be a version of the same section.
5. **RPCs** (SECURITY INVOKER, section row locked, authenticated only):
   - `save_version(section, content, base_version, make_current default true)`:
     `version_conflict` when the base is not the current version; the same text as the
     current version adds nothing; source `manual`; deletes the draft; `not_started`
     becomes `draft`.
   - `restore_version(section, version, base_version)`: a new `restore` version
     "Restored from vN", made current. The old row never changes.
6. **Has writing includes drafts:** the 0016 delete guard, `replace_outline` and
   `unlock_positioning` treat a section with only a draft as written.
7. **`outline_json`** adds per section: `words`, `version_at`, `has_draft`,
   `draft_words`, `draft_at` (additive keys).

Decisions made while building (owner to confirm):
1. **Guard, not revoke**, on `section_versions` inserts: the RPCs are SECURITY INVOKER, so a
   revoke would break them. A refusal reads like RLS (42501 "versions_rpc_only").
2. `write_next_version(section, content)` is a small read-only helper the two RPCs share (length
   check, next number). It is callable but writes nothing; the inserts stay inside the RPCs. Two
   helpers that wrote were first drafted, then folded back in, because a browser could have
   called them directly.
3. `outline_json` also returns `has_writing` (any version or a draft); step 05 uses it.
4. **Conflict** (another tab saved): the editor shows the draft, read only, until you choose.
5. **Leaving a section:** when only the draft save fails but the version saves, you can leave.
   When both fail (offline), you stay, with a note. Exit to Books waits at most 4 s.
6. A restore is refused while a draft holds text that differs from the current version
   (P0001 "unsaved_draft"); the browser always saves the draft first.
7. A chapter's pill in the manuscript list: Final when all its sections are, else the lowest
   status, and any started work shows as Draft.
8. Compare shows the text without Markdown markers. A word that only gains a space after it
   is not shown as changed.
9. Ctrl+U does nothing (no underline).
10. Decisions listed above: 06 done = every section Final ("N sections not final"); typing
    keeps Reviewed / Final; Export comes with E11; over 100,000 characters stops autosave.

No migration change, no `generate` change. One mocked test or more for each fix.

1. **05 Remove dialog and drafts.** A section with only a draft (`has_draft`, the server's
   `has_writing`) is writing, the same as a section with versions. For a chapter or section
   with writing, the dialog now says so at once: "Chapter 1 has writing" / "Section 2.2 has
   writing", "This … has writing, so it can’t be deleted." It offers only Close. Before, it
   said "Nothing is written yet" and the server refused after the click; that was true for
   versions too. A submit sends nothing. Test: `outline/t-struct.js` case 8 (changed on
   purpose) and 8b (new); the outline mock has a draft-only section.
2. **Conflict shown once.** The note "This section was saved in another tab…" repeated the
   conflict card. Now only the card shows, after a save, a restore or on open. Same fix:
   after a save met a newer version, the section used to reload, which could replace the
   text on screen when the draft had not saved either. Now the text on screen always
   stays (`adoptRemote`). Test: `write/t-fixes.js`; `write/t-versions.js` case 9 now
   expects one card and the text kept.
3. **No page scroll on Write.** The page is the window height. The manuscript list, the
   editor text and the right panel each scroll in their own column, and the side columns
   keep their background full height (design 22). Under 1,200 px the right panel sits under
   the editor in its own scrolling box (32% of the height). At 900 px the list column is
   220 px. Phones (under 700 px, the mobile layout is v2) scroll the page. Test:
   `write/t-fixes.js` at 1440 × 960 and 900 × 900 with a 1,128-word section (new mock book
   W7). It checks that there is no page scroll, that the editor, list and panel scroll on
   their own, and that the columns are full height.
4. **Back in the tab.** On `focus` or `visibilitychange`, Write reads the open section's
   current version (`kdp.getSectionHead`). If another tab saved a newer one:
   - With typing on screen, the typing goes to the server as a draft (still from the old
     version), the conflict card shows at once, and the text stays.
   - With nothing typed, the newest text simply loads ("This section was updated in another
     tab.").
   - When nothing changed, nothing happens.
   Test: `write/t-fixes.js`.
