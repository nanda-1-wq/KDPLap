## Item 1. Iframe (Kindle preview)

**Result: OK.**

- The sandbox is exactly `allow-same-origin` (js/format/kindle-preview.js:264). It has no allow-scripts, allow-popups or allow-forms.
- The sandbox is set before srcdoc (:270) and before the frame is added to the page (:275).
- The srcdoc (:76-107) holds the EPUB part bodies, parsed as strict XHTML.
  - Links with a scheme, or to a file outside the book, lose their href.
  - Links inside the book become fragment links (`#id`).
- The `<style>` holds style.css from `kdpEpub.css(style)`, which builds it from a fixed text style key, and readerCss() (:60-72), which uses design tokens only.
- The fonts `<link>` href is an app constant, and its `"` characters are escaped.
- There are no images and no remote `url()` in the frame.

Low notes:
- **L1 (low).** js/format/kindle-preview.js:105 puts the builder's CSS into `<style>${css}</style>` as it is. That is safe while css() takes only a style key.
  Suggested fix: keep user text out of style.css forever, or strip `</` from it as a guard.
- **L2 (low).** allow-same-origin is safe only because allow-scripts is never added. With both values, the frame's content could remove its own sandbox.
  Suggested fix: a unit test that asserts the sandbox value equals `allow-same-origin`.
