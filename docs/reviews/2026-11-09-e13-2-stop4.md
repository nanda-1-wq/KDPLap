## Measurement: our own host vs jsdelivr (no switch in the app)
Owner choice (Nov 9): a separate throwaway repo, not main. The 22 pinned files, byte for byte, in
`nanda-1-wq/nicheink-cdn-test`, served by GitHub Pages at https://nanda-1-wq.github.io/nicheink-cdn-test/
(the same GitHub Pages CDN as nicheink.com). Each run: a new empty Chrome profile (Chrome 156, headless,
this Mac), the 6 files of a first visit (engine JS + wasm + Classic's 4 fonts) fetched in parallel in the page,
each sha384 checked. Runs alternate the two hosts.

| Run | Host | Ready (all 6 files in, hashes checked) | On the wire |
|---|---|---|---|
| 1 | jsdelivr | 11,265 ms | 9,850,095 B (brotli) |
| 2 | own (Pages) | 9,284 ms | 11,791,016 B (gzip) |
| 3 | jsdelivr | 9,941 ms | 9,850,057 B |
| 4 | own | 4,784 ms | 11,790,985 B |
| 5 | jsdelivr | 3,928 ms | 9,850,066 B |
| 6 | own | 4,441 ms | 11,791,055 B |
| **Median** | jsdelivr **9,941 ms** · own **4,784 ms** | | |

All 18 downloads passed their sha384. The wasm is always the last file in; the time is the wasm's time.

What else differs:
- **Size:** GitHub Pages sends gzip, jsdelivr brotli: 11.79 MB vs 9.85 MB on the wire (+20%).
- **Caching:** jsdelivr says `max-age=31536000, immutable` (one year). GitHub Pages says `max-age=600` (10 minutes)
  and we cannot change its headers. After 10 minutes a returning writer's browser asks again for each file
  (a small "not modified" answer, one round trip per file), where jsdelivr needs none.
- **Edge warm-up:** run 2 was the first fetch of these files from that Pages edge; runs 4 and 6 were warm.
- **Limits:** GitHub Pages has a soft limit of 100 GB a month; at 11.8 MB a cold visit that is about 8,500 cold visits.

Repo size if the files went on `main`: **34 MB on disk, 22 files, 12.9 MiB packed** in git history (measured with
`git gc --aggressive` on a scratch repo). It stays in history even if removed later, and each engine or font
version bump adds about the same again.

Reading: 3 runs a host on one evening is a small sample; it fits the earlier note that jsdelivr swings a lot
(8.8 s, 10 s, 55.6 s, 142 s on other runs). Own hosting looked faster and steadier here, at +20% bytes and
10-minute caching. A possible design if you want it later: our host first with the same hashes, jsdelivr second
(the code already tries two servers per file). No switch is built.

The test repo stays public until you say delete (one command). It is not used by the app.

**Owner, Nov 9:** keep jsdelivr first; no self-host now.
