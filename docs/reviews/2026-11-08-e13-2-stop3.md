### A fix in a reviewed file: the first-visit progress (`js/format/engine-worker.js`)
Found while comparing with 41c: the bar stayed at 0 during the whole download, then jumped to the
end. The worker sends at most one progress message per 80 ms, timed from the worker's start, so
the chunks in its first 80 ms were never sent, and a chunk held back waited for the next one (which
can come seconds later). Now the first chunk always goes out, and a held-back count goes out when
the 80 ms window ends. On a real network the engine file streams over seconds, so the bar mostly
moved before; the start was always lost. `t-states` checks the bar is past 0 while the engine file
is still coming. The change is only in the progress messages; the real-engine tests ran again (below).
