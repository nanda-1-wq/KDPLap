## 2. The EPUB (EPUB 3, with an NCX for KDP)
**Source:** the same model and inputs as the Print PDF: `kdpFormatRules.modelOf(export_json, settings)`
(Final sections only, intro and conclusion by their part switches), `extrasFor()` (year, Also by), and
`format_json` (title, subtitle, pen name, bio). The same part order as `book.typ`: title page →
copyright → contents → Introduction, chapters, Conclusion → About the author → Also by.

**Files** (`js/format/epub.js`, pure, no DOM, Deno tested):
- `mimetype` (first, stored), `META-INF/container.xml`, `OEBPS/content.opf`, `OEBPS/nav.xhtml` (toc +
  landmarks, not in the spine), `OEBPS/toc.ncx` (spine `toc`), `OEBPS/style.css`.
- Spine, one XHTML per part (each one starts a new page): `title.xhtml`, `copyright.xhtml`,
  `contents.xhtml` (always on in the EPUB, the visible linked contents), `c01.xhtml` … (one per
  chapter, intro and conclusion included), `about.xhtml`, `also-by.xhtml`.
- Zip: `kdpCover.zip.make` (store-only, files in order, no extra field), already loaded on `book.html`.
  It is reused as is, so the 09 tests stay untouched.

**Content rules:**
- Markdown to XHTML with the md2typst grammar (p, h, ul/ol with start numbers, blockquote, **bold**,
  *italic*, `\*`, escaped markers, a single newline = `<br/>`, safe https/mailto links only). Every
  character of the writer's text is escaped; only our own tags are added (the md2typst safety rule).
  `md2typst.js` is **not changed** (print bytes stay the same). A parity test checks that both give the
  same block sequence for one corpus.
- Text goes through `kdpExportBuild.mdBody` (source labels and Verify flags removed, as in print).
  Curly quotes follow the same rule as print (Q6).
- Headings: chapter = `h1` (the label "Chapter 2" / "2" / none from `kdpFormatTypst.chapterLabel`, as
  print), section title = `h2`, a heading inside the text = `h3`. Contents: chapters, plus sections
  when "Show sections too" is on (2 levels at most). The same entries in nav, NCX and contents.xhtml.
- Print only, never in the EPUB: drop cap, running header, header title, recto start, page numbers,
  blank pages, trim, paper, ISBN (Q2).
- Copyright page: `kdpExportRules.copyright(pen, year)`, the same text as print.
- CSS from the style: headings use a generic family (serif; Modern headings sans-serif), alignment,
  sizes in em, spacing. The body has no font-family, 1em, the default line height, text-indent 1.2em,
  margins 0. No fonts are embedded (Q3). No cover (Q1).
- Metadata: `dc:title` (title) and a second `dc:title` refined as the subtitle, `dc:creator` = the pen name
  (left out when there is none, with a warning), `dc:language` `en` (the app is English only),
  `dc:identifier` = a stable `urn:uuid` derived from the book id (the raw id is never in the file),
  `dcterms:modified` = the server time of the export (`format_json.now`; tests pass a fixed date, so
  the same inputs give the same bytes).
- File name: `{title-slug}-ebook.epub`. Engine id: `epub3 · e1` (as `typst 0.14.2 · t1`).

## 3. The Kindle preview (08, Kindle mode)
- **Same source:** `kdpEpub.build()` returns `{ files, spine, nav }`. The preview renders those spine
  XHTML documents with the same `style.css`, so it never formats text again by itself.
- New `js/format/kindle-preview.js`: an `<iframe sandbox="allow-same-origin">` (scripts never run;
  the parent reads it for paging and for link clicks) with `srcdoc` = the document plus `style.css`
  plus a small reader sheet (device margins, Source Serif 4 standing in for the reader's font, the
  text size). Paging uses CSS columns, one screen at a time, with Previous / Next and the arrow keys.
  A contents link jumps to its part. External links do nothing in the preview.
- A A A sets the reader size (3 steps). The text and the EPUB do not change.
- No Typst engine: the preview builds in milliseconds, works while the engine downloads or fails, and
  works for any trim. A settings change rebuilds after 300 ms.
- Layout, Full screen, chips, footer label and states: exactly as approved in Part 0.
- Ready box in Kindle mode: as Part 0 (sections not Final, needs review, no pen name, store links).

## 5. Checks before download (like the 3 Print PDF checks; `js/format/epub-check.js`, pure)
It reads back the zip bytes it just made (a small store-only reader). A failed check means no download,
the message "The EPUB failed a check: <name>" and Try again:
1. **File structure:** `mimetype` comes first, is stored and holds `application/epub+zip`;
   container.xml points to the OPF; every manifest file is in the zip and every file is in the
   manifest; every XHTML file is well-formed XML (the browser's DOMParser, injected as
   `kdpPdfCheck.inflate` is; the Deno tests inject a strict test-only checker).
2. **Contents:** nav toc and NCX both exist, have the same entries in spine order (at most 2 levels),
   and every link (nav, NCX, contents.xhtml) lands on an existing file and id. There are no page numbers.
3. **Book details:** title, subtitle and author are equal to 04 Title and the pen name of that export's
   `format_json`. The language is `en` and the identifier and modified date are there. No ISBN is in
   the file (Q2).

**EPUBCheck (tests only, never on the server, never in the browser):** `tools/epubcheck.mjs`
downloads EPUBCheck v5.4.0 from its GitHub release into `tests/.cache/epubcheck/` (gitignored), with a
pinned sha256 (recorded at STOP 1). It runs `java -jar epubcheck.jar <file> --json`. The rule is 0 fatal,
0 errors and 0 warnings. It is used on the golden set at every STOP, and on the downloaded live files.
**Every EPUBCheck warning is reported in the STOP report, word for word, with its file. Warnings are never
silenced or filtered** (no suppression flags, no message filter, no lowered severity) (owner, Nov 23).
