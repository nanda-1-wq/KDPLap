## 6. The class change (`kp-chip`, `kp-nav`)
The Kindle chips and the Kindle pager first reused the print classes `fmt-chip` and `fmt-nav`, `fmt-nav-btn`,
`fmt-nav-label`. Old tests count those classes on the whole page (for example `t-preview.js:34`
"page buttons: 44 px, labeled" checks every `.fmt-nav-btn`, and it failed on the hidden Kindle buttons, 0 px high
in Print mode). Rather than change more old tests, the Kindle parts have their own classes with the same look:
`kp-chip` (CSS shared with `.fmt-chip`), `kp-nav`, `kp-nav-btn`, `kp-nav-label` (CSS shared with the `fmt-nav*`
rules; the Full screen dark rules use the `kp-*` names). Print selectors now match print elements only.

## 7. Bugs the tests caught, and the fixes
1. **Wrong screen numbers after the first measure.** `at()` (the screen an element starts on) kept the scroll
   position from the moment of the measure, so later lookups (contents jumps, `screenOf`) were off by the scroll.
   Fix: `at()` reads the frame's scroll position when it is called.
2. **Kindle area stayed hidden at a non-print trim (41e D).** The area's visibility is set by `paintPreview()`;
   switching to Kindle only called the Kindle paint. At print trims the engine happened to repaint, at 7 × 10
   nothing did. Fix: `setMode()` always calls `paintPreview()` first.
3. **Try again lost the focus.** Two causes: Try again hid its own box before the retry failed, and a later
   repaint rewrote the box's HTML, dropping the focused button. Fix: the box is redrawn only when its kind changes
   (nothing Final / error / none), and a Try again press is remembered (`kRetry`), so a failed retry focuses the new
   Try again and a good one focuses the book screen.
4. **The reader jumped near the end after an error.** While the error box hides the device (`display: none`), the
   frame's viewport is 0 wide; Chrome moves its scroll and fires a scroll event, and the snap handler read that as
   a page turn (screen 68 of 71). Fix: scroll events are ignored unless the frame's width equals the measured
   width, and a frame shown again with the same layout is scrolled back to the reader's screen.
5. **Tab yanked the reader to the contents.** Tab into the frame focused the first link of the document (a
   contents link on screen 3) and the browser scrolled there. Fix: only links on the current screen take Tab
   (`tabIndex` set on every page turn); the others are -1.

Further fixes found the same way:
- The skeleton was looked up from the step's root, but it is inside the device, which is in the dialog during
  Full screen (`PAGEERR … setting 'hidden'`). Now looked up in the device.
- A moved frame loads again; during that load there is no document to scroll (`PAGEERR … scrollLeft`). Guarded,
  and the module now reports `ready: false` (and `screenOf` = -1) until the reloaded frame is placed again
  (`placed()` = the measured document is the shown one).
- The frame's focus ring: `:focus` does not match an iframe while the focus is inside its document. The module
  sets `has-focus` on the frame from the frame's own focus and blur events.
