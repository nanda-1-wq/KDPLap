## 3. Safari pass of the editor (owner, STOP 4)

`node tests/browser/cover/safari-editor.mjs`: real Safari 27.0.1 through safaridriver, window 1440 × 900. **18 pass, 0 fail.**

How it stays mocked:
- WebDriver cannot answer requests. So a small server on port 5511 serves the repo and puts `tests/browser/cover/safari-stub.js` into `app/book.html` before supabase-js.
- The stub answers every Supabase call in the page, with the same answers as the Chrome mock. It refuses sockets and beacons to Supabase.
- The run fails if any request reaches the Supabase host. Here, every call was answered in the page, and the browser's resource list shows 0 requests to `supabase.co`.
- CDN files (supabase-js, fonts, pdf.js) came from the real CDNs, as in `t-safari-real.mjs`.

How it is driven, in two halves.

**1. Real input** (WebDriver element clicks, pointer actions, key actions and its file upload: the events Safari makes itself):

| Step | Result |
|---|---|
| A click on Add a heading, a double-click on its box, keys typed | typing in place starts; the text reads "Your heading Now" |
| A click on the Images tool, then on the rights box | the box is ticked |
| A file sent to the real Upload image field (WebDriver upload, a 2,880 × 1,800 PNG from `design/screens`) | stored and drawn, state ready |
| A click on Crop, then a pointer drag of 60 px on the right crop bar | the box goes from 300 to 237 px (zoom 96 %) |

**2. Scripted** (the editor's own functions, for the canvas and storage checks; no pointer):

| Step | Result |
|---|---|
| Text, effects | a heading; a full-strength shadow; curve 40: all drawn (18, 25 and 13 of 45 sample points inked) |
| Shapes | a star with a gradient and a 3 pt border: drawn (28 of 45 points) |
| Images | a 1,800 × 1,200 JPG uploaded, stored and drawn (its red corner mark read back from the canvas); a PNG keeps `image/png` and its transparency; a **6,000 × 4,000** JPG (0.8 MB) stored, screen copy 4,096 px, 329 ms |
| Crop, adjust, mask | zoom 200 % and the picture moved; Circle cuts the corner (transparent) while the middle shows; brightness 120 and sepia drawn |
| PDF page | pdf.js in Safari: a 1-page PDF, the chooser, the page stored as a 2,550 × 3,300 JPEG, source `pdf` |
| Undo, save | Cmd+Z (a key event sent in the page) takes the last layer away, and Shift+Cmd+Z brings it back. Autosave: the saved layers equal the screen; 1 visit snapshot |

## 4. The missing-picture placeholder (R13): my recommendation

**What happens now.** A picture layer whose asset id is no longer in Uploads keeps its box. render.js draws its gray stand-in, and the overlay adds a dashed red frame, a "no picture" icon, and the words "Picture missing" and "Replace it or delete it." The words stay 13 and 12 px on screen at any zoom. The layer box tells a screen reader "picture missing". The picture bar shows "Picture missing" (red, with an icon) in place of the DPI badge, and Replace fixes it. Two related states:
- a picture that is still loading: "Loading picture…", gray;
- a picture whose file did not download: "The picture did not load", plus Retry in the bar.

**Recommendation: yes, it blocks export.** Built as a Must fix, **C15**: "<name> is missing: it was removed from your uploads. Replace it or delete it." It uses the C10 row style, so the chip and the header count it ("Fix N problems before export.").
- **Why:** the server already refuses such an export. 0030's `cover_rights` raises an error when a printed picture's asset has no row for the user. So the export could never succeed; the client only says it before the export starts, with a fix. A hidden or excluded missing picture does not print, so it is not counted.
- **Where it lives:** C15 runs only when the editor passes the list of missing assets (`checks.run(cover, { missing })`). Without that list, `checks.run` gives exactly what it gave before, so the Part 1 tables do not move.
- **If you say no:** two lines in `editor.js` drop the `missing` option, and the placeholder stays.

## 5. Findings and "New, your call"

### Findings (no decision needed)

**F1. Crop and keys: a bug found by the new tests, fixed.** Crop puts focus on its Zoom slider. Escape and Cmd+Z did nothing there, because the editor ignored every key inside an input. Now Escape always ends crop mode, and undo and redo also work from a slider or a check box. Typing fields keep their own keys. This touches every popover with a slider (Adjust, Text effects, Opacity): Cmd+Z there now undoes instead of doing nothing.

**F2. Files differ from the plan's list.** The plan named `js/cover/crop.js` and the tests `t-mask`. **F3. supabase-js sends an upload as multipart form data.** The file part carries the Blob's own type. The mock now reads that part, as Storage does, and checks 0030's path rule and the two allowed kinds.

**F5. A crop could outlive a lock.** A picture locked or hidden from the Layers panel stayed in crop mode, so Zoom and the arrow keys could still move a locked picture. Crop mode now ends whenever its picture is locked, hidden or removed, from any place (new check in `t-crop.js`).

**F6. The Uploads list held big pictures in memory.** The first build kept a 4,096 px screen copy for every Uploads tile. Now a tile keeps only its thumbnail (N3).
