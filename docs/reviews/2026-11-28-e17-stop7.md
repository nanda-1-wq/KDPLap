## 2. How each step works

**Step 1 · Rows (83).**
- `js/format-rules.js:76` `PART_ROWS`: Title page, Copyright, Dedication, Epigraph, Contents (+ Show sections too, Kindle note), Foreword, Preface, Introduction, Conclusion, Acknowledgments, Notes and references (`later`, "Comes later", no switch), About the author, Review request page, Also by. `part: true` rows are the 8 `book_parts` kinds.
- `js/book-format.js:131` `bp` holds the `book_parts_json` read; `:229` `readParts`, `:232` `partsState` (ready / off before 0035 / error). `:285` `loadData` reads it with format_json and export_json.
- `js/book-format.js:998` `partRowHtml`: a 32 px `<label class="fmt-row fmt-check fmt-bp">` (accepted 08 exception, whole row clickable). When on: the pill from `js/format-rules.js:291` `partPill` (Empty dashed / Draft outline / nothing for Final / "Fixed text" for the review request / "N book(s)" for Also by, from `also_by` entries with `valid`), then "Open in 06" (`:148` `partHref` = `book.html?id=…&step=6&part=<id>`; none for the review request, as 83). The switch is `data-fmt-bp="<kind>"`.
- One source of truth: the switch writes `book_parts.enabled` through `kdp.parts.set` (the 06 menu writes the same column). 08 never keeps its own copy.

**Step 2 · Ready box.**
- `js/book-format.js:147` `notReady()` = `partsNotReady(parts, files)` (`js/format-rules.js:305`). `files` is `exp.book_parts` = 0035 `book_parts_files` (built on `part_file_list`). A part is "not ready" when it is on and not in that list. No Final rule in JS.
- `:832` `partsBoxHtml`: amber `alert-warning` with the warning icon, bold "N book parts are not ready." and "They are left out of the files until they are Final." (singular: "1 book part is not ready. It is left out … until it is Final."). One line per part (`partWhyText`, `js/format-rules.js:320`: "X is a Draft." / "X is on but empty." / "Also by has no books.") with an "Open in 06" link.
- `:843` `paintReady` puts the parts box first, then the existing warnings, then the 83 note (`:841`). `:880` `paintKindleReady` shows the same box in Kindle view (the EPUB leaves them out too).
- It never blocks export: nothing in the Export files panel reads it. `:1400` `isDone` is unchanged (Print PDF only).

**Step 3 · Kindle preview.** No code change. `kdpEpub.build()` already renders `model.bookParts`, and the preview shows the EPUB spine. `refreshParts` (`:244`) schedules a Kindle rebuild after a switch. Tested (section 4).

**Step 4 · E11 dialog (Q-4).** `js/export-dialog.js` has no About row any more. `js/export-rules.js:75` `aboutInFile`, used in `defaults()` (`:66`) and again at every load (`js/export-dialog.js:568`). The DOCX record sends `about: true` exactly when About is Final in the file, so the 0035 guard builds the DOCX snapshot from it. The 08 Word row label stays "Word (.docx) or Markdown (.md)" (`js/format-export.js:181`, unchanged).

**Step 5 · States.**
- Loading: the 08 loading line until the parts read is back (one `Promise.all`).
- Saving: `:264` `savePart` marks the row `aria-busy`, shows "Saving…", and keeps the box on the asked value; clicks while saving do nothing (`:1071`).
- Save failed: the box goes back; a red line under the row (warning icon + "Not saved.", or "You are offline. Not saved.") with Retry (44 px), the switch `aria-describedby` it (`:1150` Retry resends the same value).
- Parts read failed: one red line "Book parts could not load." with Retry (`:924`); the rest of 08 works. Before 0035 (`PGRST202`/`42883`) the part rows are hidden, as in 06.
- After a save: `refreshParts` reads export_json and book_parts_json again, rebuilds the model, both previews, the Ready box and the 08 mark (`readMarks`).
- Changed mark: not rebuilt. 0035 `part_key_extra` already puts every on part in `format_key` and `epub_key`. New SQL checks in `t0035.sql`: after a PDF and an EPUB, turning off the Final dedication (in the file) marks both changed; turning it on again makes both current; a Draft part turned on (not in the file) also marks both changed, as design 83's "Changed mark" row says ("turning a part on or off marks the Print PDF and the EPUB as changed"); off again, current.
