## 3. Fixes 1 to 5 (Claude chat review)

### Fix 1. Links need a real host or address
- **Code changed, not the test.** `hrefOf()` now first checks the text as typed:
  `https://` (or `http://`) must be followed by a real host (letters or digits, labels split by dots,
  optional `user@` and `:port`, or `[IPv6]`); `mailto:` must be followed by `name@domain.tld`.
  Only then is the URL encoded and parsed. The cause: the URL parser reads `https:///nohost` as the host
  `nohost`, so a parser check alone can never catch it.
- **The old expectation is back:** `[n](https:///nohost)` stays plain text. New plain-text cases:
  `https://`, `https://.com`, `https://-a.com`, `https://a..com`, `https://@e.com`, `mailto:`,
  `mailto:nobody`, `mailto:a@b`, `mailto:@b.co`. New link cases: a port, a user, `http://localhost`,
  `https://e.com?x=1`, a Unicode host (`b%C3%BCcher.de`), `mailto:` with `?subject=`.
- **The one failing links test was:** `**[bold](https://e.com/b)**`. The test expected
  `<strong><a …>bold</a></strong>`; the EPUB gave `**<a …>bold</a>**`. The EPUB was right: print
  (md2typst) takes links out before it reads stars, so it prints
  `\*\*#link("https://e.com/b")[bold];\*\*`, the stars as typed around the link. The expectation now
  matches print, and `tests/epub-parity.test.js` checks both sides. (`[**bold**](url)` is bold in both.)
- **Print differs on purpose:** print still links `https:///nohost`, `mailto:nobody`, `mailto:a@b`,
  `https://.com` and also `https://exa<mple.com` (its rule allows `<`). The parity test asserts this
  difference. md2typst.js is not changed (print bytes stay the same).

### Fix 2. Headings nested properly
- **The smallest fix:** in a chapter, until the first section title, every heading in the text moves
  up one level (h3 → h2, h4 → h3). After a section title (h2) nothing changes. Equal headings stay
  equal. It is one number passed to `blockList(md, top)`: `top` is 1 before the first section title,
  2 after it. The h2 then has the section-title look (same as print for an in-text `#`).
- **Tests:** unit (`top` 1 and 2, equal headings, a heading in a quote); a book with an untitled first
  section, a titled one, then an untitled one gives h1, h2, h2, h2, h3, h3; and every golden EPUB
  is scanned: no heading is more than one level below the one before it.
- **How print handles the same case:** `mdBody` adds one `#` to every heading in the text, so in print
  an in-text `#` is level 2 and `##` is level 3. In an untitled section print goes from the chapter
  (level 1, `#chapter(…)`) straight to level 3. Measured in the parity test with
  `## Tip` in an untitled section, then a section "Steps" with `## Inside`:
  print levels **1, 3, 2, 3**; EPUB levels **1, 2, 2, 3**. The parity test asserts both lists.
- **Still open (not fixed, print has it too):** a writer can skip levels inside the text, for example
  `#### Tip` right after a section title (EPUB h2 then h5, print 2 then 5). None of our fixtures do it.
  A fix would renumber the heading levels in each section. It is the owner's choice (question Q-B below).

### Fix 3. Format characters are never removed or changed
- No character of the writer's text is removed or changed because of the format-character rule.
  Test "format characters: never removed or changed": 13 format characters in the title, subtitle,
  bio and text all reach the files; the ZWJ family emoji, the England flag (tag characters) and soft
  hyphens stay whole. Golden `format-chars.epub`: EPUBCheck 0/0/0.
- **The rule, word for word.** Kindle Publishing Guidelines v2026.3, §6.7 "Use Supported Characters
  and Spaces", **page 28**:
  > The only supported spaces are the normal space, the non-breaking space (&nbsp;), and the zero-width
  > non-joiner (&zwnj;). Use of any other space can break the selection, dictionary lookup, and line-wrap
  > algorithms.
  >
  > Do NOT use Unicode format characters, as they may cause problems.

  Related, §9 "QA Standards", **page 30**:
  > Make sure your book is free of typos, such as numbers in place of letters, letters in place of numbers,
  > incorrect punctuation, soft hyphens, missing letters, HTML tags in place of characters, and junk
  > characters.
- **What the rule would touch** (Unicode 16 general category Cf, 170 code points). What a writer would really type:

  | Character | Where it shows up in real text | What removing it would do |
  |---|---|---|
  | U+200D zero width joiner | every multi-person and many profession emoji (👨‍👩‍👧, 👩‍🏫), some flags; Devanagari, Arabic and Indic shaping | the emoji falls apart into separate people; some scripts render wrong |
  | U+E0020 to U+E007F tag characters, U+E0001 | the England, Scotland and Wales flags | the flag becomes a plain black flag |
  | U+00AD soft hyphen | pasted from Word or a website; §9 also calls it a typo | the word loses its hyphen hint (it looks the same) |
  | U+200C zero width non-joiner | Persian, Hindi, German typesetting | 6.7 **allows** it as a space, yet it is Cf |
  | U+200B zero width space | pasted web text, Thai and Khmer line breaks | words join, no break point |
  | U+200E, U+200F, U+061C direction marks | text with Hebrew or Arabic next to English | punctuation can jump to the wrong side |
  | U+202A to U+202E, U+2066 to U+2069 direction embeddings and isolates | the same | the same |
  | U+2060 word joiner | rare, pasted | a line may break there |
  | U+FEFF zero width no-break space (BOM) | pasted from Windows files, at the start of a line | none visible |
  | U+2061 to U+2064 invisible math operators, U+0600 to U+0605, U+06DD, U+070F, U+0890, U+0891, U+08E2 (Arabic and Syriac signs), U+180E, U+FFF9 to U+FFFB, U+110BD, U+110CD, U+13430 to U+1343F, U+1BCA0 to U+1BCA3, U+1D173 to U+1D17A | almost never in a nonfiction book | the sign or the shaping it controls is lost |

  The space rule in the same section would also touch other spaces (for example U+2009 thin space,
  U+202F narrow no-break space, U+3000 ideographic space). The EPUB keeps them all.
- **Already changed before the EPUB (shared with print, the editor and DOCX):**
  `kdpMarkdown.normalize` (through `mdBody`) turns a no-break space U+00A0 in section text into a normal
  space. This is old editor behaviour, not the Guidelines; 6.7 allows the no-break space. The EPUB
  follows print here. Titles, the pen name and the bio do not go through it.
- **What the EPUB does remove** (forbidden by XML or HTML, as before): C0 controls except tab and new line,
  and DEL (the same as print); tab becomes a space (as print); C1 controls U+0080 to U+009F (XML 1.0
  allows but discourages them; HTML, which EPUB 3 XHTML must follow, does not allow controls in text);
  U+FFFE and U+FFFF; lone surrogates. Only the C1, U+FFFE, U+FFFF and surrogate removal is EPUB-only; the
  parity test asserts it. Noncharacters like U+FDD0 and U+1FFFE are kept; an experiment gave EPUBCheck
  0/0/0 on them.
- **The owner decides** (question Q-A below).

### Fix 4. Every special character is a `\u` escape
- Cause: the file tools turn `\u` escapes into raw characters (some, not all: U+2018 and U+FFFF
  became raw, U+0085 and U+D800 stayed escapes). They also did it inside `epub.js`.
- A script now rewrites the files (`scratchpad/scripts/to-escapes.py`): in the fixture, the 3 test files
  and `tests/lib/xml-strict.js` every code character above U+007E is a `\uXXXX` escape (emoji as
  surrogate pairs), and comment lines use plain ASCII (`=`, `-`, `->`). These 5 files are now pure ASCII.
  In `epub.js` and `epub-check.js` every code line is ASCII too (the curly quotes, primes, `·` and the
  combining range are escapes); only their comment banners keep the project's `═` and `·`.
- **Byte proof** (`LC_ALL=C grep`):

### Fix 5. One main title (E20006) and contents links (E24010)
- **Guidelines wording.** E20006 (page 105): "There are more than one title defined in OPF metadata."
  The fix it gives: declare "title-type" "main" for one of them. E24010 (page 104): "Hyperlink not
  resolved in toc (One possible reason can be that the link points to a tag with style display:none)";
  its example moves an id from `<body>` to a child element.
- **Builder tests** (every golden EPUB):
  - "E20006": exactly one `dc:title` refined `title-type` `main`, equal to 04 Title; with a subtitle,
    a second `dc:title` refined `subtitle`; without one, only the main title.
  - "E24010": every link in the toc nav, the NCX and contents.xhtml lands; no body has an id; no link
    with an id lands on `<body>`; no target or parent is `hidden` or has a style that hides it; the toc
    nav is not hidden; style.css has no `display` or `visibility`.
- **The checker enforces both too** (added to `epub-check.js`, the plan's checks 2 and 3):
  "not one main title (E20006)" for two mains, a missing main, or an extra untyped title;
  "a contents link lands on the body", "a contents link lands on hidden text" (the `hidden` attribute, or
  `display: none` / `visibility: hidden` in a style on the target or a parent), and "style.css hides
  text". Each has a broken-sample test.
