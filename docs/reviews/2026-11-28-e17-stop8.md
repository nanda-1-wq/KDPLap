## How steps 1 to 4 work

1. **Part items in 07 group 1.**
   - `js/qc-rules.js:486` `partItems()` reads `qc_json.book_parts` (0035).
   - A part gives an item only when it is on, is not a fixed-text part (review request, Also by: `PART_FIXED`), and is not already in the files list (`data.book_parts`, the server's `part_file_list`).
   - Empty means no current version or 0 words, and gives the key `{part_id}|none`. Not Final gives the key `{part_id}|{version_id}`.
   - `section_id` is null. `:585` adds the items to group 1 after the section items and chapter_review, in book order (`from` = the index).
   - `js/book-qc.js:188-232`: `isPartItem`, `partOfItem`, "Book part" in `whereOf`, `rowLink` gives `Open in 06<span class="sr-only">: name</span>` to `?id=…&step=6&part=<id>` (a plain link, as in 08), and `rowText` makes the name bold.
   - **Also by** (the task asked me to decide): it never gives a 07 item. The server's `qc_inputs_key` does not hold the Also by list (t0035 proves this now), so such an item could never go out of date or clear on the next run. 08 still warns about Also by.
2. **No Mark as OK.**
   - `js/book-qc.js:232` draws no button for part items. `:598` `markOk` returns early.
   - The server refuses them too: 0035 `qc_dismissed_rule_check` (`rule not in ('part_empty','part_not_final')`). It was there already, so I did not stop.
   - Proofs: t0035 "but have no Mark as OK" (23514, both rules); `tests/limits-parity.test.js` (0035 refuses exactly `NO_OK`); the browser test (the mock gives the same 23514).
3. **Verdict and Out of date.**
   - The part items are warnings, so the verdict stays "Ready for Format, with N warnings" (tested).
   - Out of date comes only from comparing 0035 `qc_inputs_key` with the run's key. There is no new JS rule.
   - t0035 proves that the key changes on: a part turned on, Final, a new version, a part turned off again.
   - The new proof shows the key does not change when the Also by list changes.
   - The browser test runs each change against the mock's copy of the key.
   - The stale text (`js/book-qc.js:149`) now says "…a section's status, a book part or 08 settings changed…".
4. **The 06 states.**
   - `js/book-write.js:1535` builds the save-failed footer: icon, then "Not saved. Check your connection." (or "Not saved. You are offline." when `navigator.onLine` is false), Retry, then "Your text stays on screen. The app tries again when you are back online."
   - `:1712`: Retry calls `saver.retry()`.
   - `:2046`: `online` retries when a save failed and text is still unsaved; `offline` redraws the footer.
   - `:1264`: the part loading lines. `:1571`: the Checks tab.
