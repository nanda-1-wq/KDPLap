## Migration 0024_kept_findings.sql (STOP 2)
Table `public.kept_findings`:
| column | rule |
|---|---|
| id | uuid pk, gen_random_uuid() |
| user_id | not null, default auth.uid(), → auth.users on delete cascade |
| section_id | not null, → sections on delete cascade |
| type | 'objective' \| 'voice' \| 'drift' |
| message | 1 to 300 chars, not blank (same caps as 0022) |
| quote | 1 to 300 chars not blank, or '' for an objective gap only |
| check_at | timestamptz: required when quote = '' (the `section_checks.checked_at` of the check it came from), null otherwise |
| created_at | default now() |

Different from your expected shape: **one extra column, `message`**. Why: the kept list (3b, 11) shows the message, and the finding may no longer be in the current check. A check can also have 2 gaps with the same type and an empty quote, so the message is what tells them apart.

- RLS on. Policies: select, insert and delete own rows only. Insert also needs the section to belong to the user. No update policy, and `update, truncate` revoked from anon and authenticated.
- Guard trigger (before insert, set search_path = ''), like 0008 `competitors_limit`:
  - A gap row: `check_at` must equal the section's current `section_checks.checked_at`, and that check must hold an objective gap with this exact message (P0001 `kept_gap_not_in_check`). Gap rows of this section from older checks are deleted in the same trigger ("for this check only", so they never pile up).
  - At most **50 kept rows per section** (P0001 `kept_limit`), with a lock on the section row so two tabs cannot pass the cap together.
- Unique indexes: `(section_id, type, quote) where quote <> ''` and `(section_id, check_at, message) where quote = ''`. A double click gives 23505, which the browser reads as "already kept".
- Index on user_id. Comments on the table and the function. Execute on the trigger function revoked.
- Header notes the read-only pre-check: last migration 0023, 20 public tables, no kept_findings.

## Browser part (STOP 3)

### New `js/finding-rules.js` (pure, `globalThis.kdpFindingRules`), loaded in `app/book.html` before write-checks.js
- `severity(type)`: drift, objective → 'major'; voice → 'minor'. The one shared map.
- `isKept(finding, kept, checkedAt)`: quote finding: same type and exact quote. Gap: kept row with the same message and the same check time (compared with Date.parse).
- `view(row, kept, text, old)`: splits a saved check into open major (in text order of the quote; quotes not in the text and gaps last), open minor, kept, and the pass rows (owner rule above).
- `fixMajor(row, kept, text, old)`: the queue items: major, quote not '', quote in the text, not kept, check not out of date. Button shows only when length >= 2.
- `tabCount(warnings, view, old)`: code warnings + open major, 0 major when out of date.
- Node-free deno test `tests/finding-rules.test.js` (severity map, sort order, kept matching for quotes and gaps, N rule edge cases, count).

### `js/write-checks.js`

- `findingHtml`: type line "Drift · Major" / "Voice · Minor" (minor uses the gray info icon); button "Fix" with aria-label "Fix with AI: drift"; "Keep as is" text button; gap keeps the "Missing from the text" tag, no Fix.
