## 3. Migration 0028 (columns, checks, RLS, guards)

Full SQL: `supabase/migrations/0028_quality_control.sql` (E14.1). House rules, as 0022 to 0027: every
function `set search_path = ''` and schema-qualified names; `case`, not `and`, in jsonb shape
checks; structure checks only (our code decides content); a header that says what was checked
before writing; grants at the end.

### 3.1 `export_json` gets `word_target`

`create or replace function public.export_json` with one new key per section:
`'word_target', s.word_target` (int, 0 to 10,000, or null). Nothing else changes. Same return
type, so grants stay. `t0025.sql` checks keys with `?&`, not an exact list, so it still passes.

### 3.2 The Out of date key (D5)

Two SQL functions, SECURITY INVOKER (RLS as the caller), `stable`:

- `qc_versions(p_book_id uuid) → uuid[]`: the current version id of every section whose
  current version is not blank, every chapter kind, any status, ordered by chapter position,
  then section position. Empty array when none.
- `qc_inputs_key(p_book_id uuid) → text`: `md5` of one `jsonb` with every input the free rules
  read besides the text. Null for a book the caller cannot see.

What `qc_inputs_key` holds:

| Input | Source | In D5? | Read by |
|---|---|---|---|
| Chapter ids, kinds, titles, objectives, order; section ids, titles, order | `chapters`, `sections` | yes (titles) | labels, pointers, topic words; the number rule reads objectives through `knownOf` |
| Word targets | `sections.word_target` | yes | 80% rule |
| Trim | `book_briefs.trim_size` | yes | page estimate |
| Research sources (kind, body, citation) | `research_sources` | yes | number rule, sources named |
| Positioning lock time | `positioning.locked_at` | yes | promise lock state |
| Brief fields `knownOf` reads (topic, reader, problem, promise, options stance, standout, references), insights, competitor titles | `book_briefs`, `research_insights`, `competitors` | yes (Q3) | the number rule reads all of `knownOf` |
| Section status and `needs_review`, chapter `needs_review` | `sections`, `chapters` | yes (Q3) | group 1 |
| Book title, subtitle; positioning one sentence, reader promise | `books`, `positioning` | yes (Q3) | disclaimer words, topic words |
| 08 style (default `classic`), 08 copyright part (default on) | `book_formats` | yes (Q3) | missing characters, disclaimer |

The lock time goes in as an epoch number: a `timestamptz` in JSON prints in the session's time
zone, and the key must be the same in every session. One-row tables use left joins and the 08
defaults, so an empty row (or the first 08 row, with defaults) never puts a run out of date.

**Current** = `versions = qc_versions(book)` **and** `inputs_key = qc_inputs_key(book)`.
Not in the key on purpose: drafts (`section_drafts`), runs, kept findings, `qc_dismissed`,
`book_checks`, `ai_usage`, exports, `books.updated_at`. A Mark as OK never makes the run
Out of date (dismissals are applied when the screen shows the results).

### 3.3 `qc_runs` (one row per run, written by the browser)

| Column | Type | Rule |
|---|---|---|
| `id` | uuid pk | `gen_random_uuid()` |
| `user_id` | uuid not null | default `auth.uid()`, fk `auth.users` cascade |
| `book_id` | uuid not null | fk `books` cascade |
| `versions` | uuid[] not null | 1 to 2,000, no nulls (as `book_exports`) |
| `inputs_key` | text not null | `^[0-9a-f]{32}$` (md5) |
| `results` | jsonb not null | `qc_results_ok(results)` and `octet_length(results::text) <= 400000` |
| `sections` | int not null | sections with text checked, 1 to 2,000 |
| `words` | int not null | 0 to 1,000,000 |
| `style` | text not null | `classic`, `modern`, `clean`, `warm` (the font the check used) |
| `created_at` | timestamptz | default `now()`: the run time shown on screen |

`results` shape (structure only, helper `qc_results_ok` and `qc_item_ok`):
`{ items: [...], more: {"1": n, ...}, sources: [...], notes: { unsaved: n, running: n } }`.
- `items`: at most 400. Each `{ g, rule, key, section_id, version_id, start, end, message, quote }`:
  `g` 1 to 7 but not 6; `rule` one of the rule ids in §5 (`qc_rule_ok`); `key` 1 to 300
  characters; `section_id`, `version_id` uuid or null; `start`, `end` int or null
  (0 ≤ start ≤ end); `message` 1 to 300, not blank; `quote` 0 to 300.
- `more`: issues past the cap, per group (the screen says "and 12 more").
- `sources`: at most 50 `{ citation (1 to 200), sections: [uuid] (at most 400) }`.

Row Level Security and privileges:
- `qc_runs_select_own`: `user_id = auth.uid()`.
- `qc_runs_insert_own`: `user_id = auth.uid()` and the book is the caller's.
- No update, no delete: `revoke update, delete, truncate ... from anon, authenticated`.
- anon has no insert either. It has no uid, so the SECURITY DEFINER guard would take it for the
  server and answer `qc_stale` before the policy refuses the row.

Guard `qc_runs_guard` (before insert, every role; SECURITY DEFINER only for the clean-up,
as `book_exports_guard` in 0025; another user's book returns early and the policy refuses):
- a. `user_id` is the book's owner. P0001 `qc_owner`.
- b. The book row is locked (`for update`), so two tabs cannot pass the cap together.
- c. `versions = qc_versions(book)` and `inputs_key = qc_inputs_key(book)`, else P0001
  `qc_stale` ("Your book changed while the checks ran. Run again."). Same pattern as
  `export_stale` in 0027.
- d. Keeps the newest 5 runs per book (deletes older ones of the same book and user).
- A run never touches `books.updated_at` (a check is not an edit; Books order stays).

### 3.4 `qc_dismissed` (Mark as OK, written by the browser)

| Column | Type | Rule |
|---|---|---|
| `id` | uuid pk | |
| `user_id` | uuid not null | default `auth.uid()`, fk cascade |
| `book_id` | uuid not null | fk `books` cascade |
| `section_id` | uuid null | fk `sections` cascade; null for a book-wide issue |
| `rule` | text not null | `qc_rule_ok(rule)` or `promise_drift` |
| `issue_key` | text not null | 1 to 300 characters, not blank |
| `label` | text not null | 1 to 300, not blank: what "Marked as OK" lists |
| `created_at` | timestamptz | default `now()` |

- Unique `(book_id, rule, issue_key)`. A second Mark as OK (double click, other tab) gives
  23505, which the browser reads as done.
- RLS: select own; insert own (book is the caller's); **delete own** (Undo needs it, designs
  53 and 55 F). No update (privilege revoked).
- Guard `qc_dismissed_guard` (before insert, SECURITY INVOKER, every role):
  a. owner of the book (P0001 `qc_dismissed_owner`);
  b. `section_id` null or a section of this book (P0001 `qc_dismissed_section`);
  c. book row locked, at most 500 rows per book (P0001 `qc_dismissed_limit`).
- No automatic clean-up: a dismissal whose key no longer matches stays hidden from the list
  and harmless (see §10, R7).

### 3.5 `book_checks` (promise check, one row per chapter, written by the server only)

| Column | Type | Rule |
|---|---|---|
| `chapter_id` | uuid pk | fk `chapters` cascade |
| `user_id` | uuid not null | fk cascade |
| `book_id` | uuid not null | fk `books` cascade |
| `verdict` | text not null | `keeps` or `drifts` |
| `reason` | text not null | 1 to 300 characters, not blank |
| `quote` | text not null | `''`, or 1 to 300 characters not blank |
| `section_id` | uuid null | fk `sections` on delete set null; must be null when `quote = ''` |
| `unsourced` | text[] not null | default `{}`; at most 10 items of 1 to 20 characters (the 0017 rule) |
| `versions` | uuid[] not null | the versions the check read, 1 to 12 (0016 caps 12 sections a chapter) |
| `words` | int not null | 50 to 6,000 |
| `inputs_key` | text not null | `^[0-9a-f]{16}$` (keyHash, §4.9) |
| `checked_at` | timestamptz not null | the function's clock |
| `created_at`, `updated_at` | timestamptz | `set_updated_at` trigger |

- RLS: `book_checks_select_own` only. `revoke insert, update, delete, truncate` from anon and
  authenticated. The service role upserts on `chapter_id` (as `section_checks`, 0022).
  The browser never writes an AI result.
- Guard `book_checks_guard` (before insert or update, every role):
  a. `user_id` and `book_id` are the chapter's owner and book, and the chapter kind is
     `chapter` (P0001 `book_check_owner`);
  b. `section_id` null or a section of this chapter (P0001 `book_check_section`);
  c. every id in `versions` is a version of a section of this chapter, no repeats
     (P0001 `book_check_version`).
  Each is checked on insert, and on an update only when its column changes (as 0022). A book
  delete cascades in trigger-name order, which nothing promises, so the `set null` on
  `section_id` may meet a chapter or versions already gone.
- No delete is needed: rows go with their chapter (cascade). A new check replaces the row.

### 3.6 Reads: `qc_json(book)` and `qc_mark(book)`

`qc_json(p_book_id uuid) → jsonb`, SECURITY INVOKER, one statement (one snapshot), null for a
book that is not the caller's:

```
{ data:        export_json(book)            -- with word_target (3.1)
  versions:    qc_versions(book)
  inputs_key:  qc_inputs_key(book)
  format:      { style, parts, chapter_label } of book_formats, or null before 08
  positioning: { locked_at, one_sentence, reader_promise, approach, lacks,
                 selling_points, focus_tags } or null
  last_run:    { id, created_at, versions, inputs_key, results, sections, words, style } or null
  current:     true when last_run matches versions and inputs_key
  dismissed:   [{ id, section_id, rule, issue_key, label, created_at }] newest first
  promise:     [book_checks rows of the book, without user_id]
  now:         server time }
```

`qc_mark(p_book_id uuid) → table (checked_at timestamptz, current boolean)`: no row before the
first run. Small: no text leaves the database. The shell reads it for the 07 mark.

### 3.7 Grants

`revoke execute ... from public, anon` and `grant execute ... to authenticated` on `qc_versions`,
`qc_inputs_key`, `qc_json`, `qc_mark` and the shape helpers. The three guards: execute revoked
from public, anon, authenticated. Every new table: RLS on.

## 4. Generate stage `promise_check` (E14.5)

One call checks one chapter. Never the whole book (CLAUDE.md §5).

**4.1 Input.** `{ stage: "promise_check", bookId, chapterId }`. Exactly these keys, uuids,
body at most 2 KB (`BODY_BYTES`). The browser sends no text and no prompt.

**4.2 Read (RLS as the caller).** New store method `getPromiseContext(bookId, chapterId)`: the
book, the positioning row, `outline_json(book)`, the current versions of the chapter's
sections, their runs. Null for another user's book or a chapter not in it (404).

**4.3 Checks before any money is spent, in this order:**

| Check | Error |
|---|---|
| The chapter is in the book and its kind is `chapter` | `not_found` |
| Positioning is locked | `positioning_not_locked` |
| At least one section of the chapter has text | `nothing_to_check` |
| No fresh Generate run in the chapter (0020 rule) | `run_in_progress` |
| 50 to 6,000 words (`md_word_count` rule, sections joined) | `check_too_short` / `check_too_long` with `words` |
| Monthly limit with the reserve (input estimate + max_tokens), 10 calls a minute | `monthly_limit` / `rate_limited` |

Unsaved drafts do not block: QC checks saved text (same as the free checks).

**4.4 Prompt** (server side, `lib/promise_check.ts`). System: the data-tag rule and the
injection guard as `SECTION_CHECK_SYSTEM`; the task: does this chapter keep the locked
reader promise and its own objective. Drift = a new promise, audience or angle; a bigger
promise than the reader promise; a cure or guaranteed result; or a chapter that leaves its
objective. Grammar, numbers and sources are not its job (the app checks those).
User message, all through `asData`:
`<locked_positioning>` (one sentence, reader promise, approach, lacks, selling points, focus
tags), `<chapter>` (number, title, objective), `<chapter_text>` with one
`<section number="2.1" title="…">` block per section with text, in order.

**4.5 Output.** JSON schema `{ verdict: "keeps" | "drifts", reason: string, quote: string }`,
all required, no other keys. Our code decides what is kept:
- `verdict` not one of the two → failed, not counted (`ai_unavailable`).
- `reason`: one line (`cleanLine`, no em dashes), cut at a word to 300 characters
  (`cutWords`); blank → failed, not counted.
- `quote`: for `drifts`, found exactly in one section's text (`findQuote`), which gives
  `section_id`; not found → `""` (the verdict stays, with no spot). For `keeps`: always `""`.
- `unsourced`: numbers in the reason that the positioning, objective and chapter text do not
  have (`unsourcedList`, chapter references taken out with `withoutSectionRefs`). The screen
  shows them with "Verify: no source" (CLAUDE.md §5).

**4.6 Limits** (`lib/limits.ts`): `STAGES` + `promise_check`; `MODEL_FOR_STAGE` Sonnet 5.5;
`BODY_BYTES` 2,048; `TIMEOUT_MS` 60,000; `MAX_TOKENS` 500; `PROMISE = { minWords: 50,
maxWords: 6000, reasonChars: 300, quoteChars: 300 }`. Mirrored in the browser and checked by
`tests/limits-parity.test.js`.

**4.7 Save, usage, failure.** `save` upserts `book_checks` with the service role (guard §3.5).
A save failure → `counted: false`, `server_error`, as `section_check`. Every call that reached
the provider is logged in `ai_usage` (`stage: "promise_check"`, `book_id`, tokens, status,
`counted`). A failed or refused AI answer, or `max_tokens`, is not counted (`readReply`). A
refusal before the call writes no usage row. Stop in the browser stops the next chapter only;
the call in flight finishes on the server, is saved and counts its tokens (CLAUDE.md §5: a
stop by the user counts).

**4.8 Reply.** `{ stage, chapter_id, verdict, reason, quote, section_id, unsourced, words,
versions, inputs_key, checked_at }`.

**4.9 Key.** `promiseKey` = `keyHash` of: the chapter's version ids (sections with text, in
order), chapter title, objective, positioning `locked_at`. TS in `lib/promise_check.ts`, the
same function in `js/qc-promise-key.js`, a parity test runs both (as `section-check-key`).
A chapter is Out of date when the key on screen differs from the saved one.

**4.10 Files.** New `lib/promise_check.ts`; changed `lib/limits.ts`, `lib/stages.ts`
(entry), `lib/types.ts` (`getPromiseContext`, `savePromiseCheck`), `lib/common.ts`
(`Outcome.promise`), `lib.ts` (re-exports), `index.ts` (two store methods), `test_fakes.ts`.

## 5. Free rules (`js/qc-rules.js`, E14.2)

Pure, no DOM. `kdpQcRules.run(qcJson) → { items, more, sources, notes, sections, words, style }`.
It reuses the 06 and Export rules so the screens never disagree: `kdpExportRules.model()`
(all sections with text, `include: 'all'`), `kdpTextChecks.check()` rows, `sentenceKeys`,
`knownOf`, `ending`, `kdpWords.count`, `kdpWords.pages`. Offsets are in the version's
Markdown, the same as 06 "Show". Lists live in `js/qc-lists.js` (data only).

Key column = the Mark as OK `issue_key`. `h()` = `keyHash` of the normalized text, so long
sentences fit in 300 characters. "Spot" = what "Open in 06" marks.

| G | Rule id | Finds | Spot | Mark as OK key |
|---|---|---|---|---|
| 1 | `not_final` | A section with text that is not Final | section | `section|version` |
| 1 | `no_text` | A section with no saved text | section | `section|none` |
| 1 | `needs_review` | `sections.needs_review` | section | `section|version` |
| 1 | `chapter_review` | `chapters.needs_review` ("Open in 05", not in the design, Q8 yes) | chapter | `chapter|review` |
| 1 | `under_target` | Words under 80% of the section's target (06 rule) | section | `section|version` |
| 1 | `stopped_run` | Current version is `partial` (a stopped Generate run) | section | `section|version` |
| 1 | `cut_off` | Ends mid-sentence (`kdpTextChecks.ending`) | cut piece | `section|h(piece)` |
| 2 | `verify_mark` | " [Verify: no source]" left in the text | sentence | `section|h(sentence)` |
| 2 | `number_no_source` | A claim number with no source and no mark (06 `number` row) | number | `section|h(sentence)` |
| 2 | `source_not_named` | A source label or a source with no name (06 `source` row) | match | `section|h(sentence)` |
| 2 | (info) | Sources named in the text: a research source counts as named in a section when the text has its first author's surname or 3 words in a row from its title. Approximate, never counted. | | |
| 3 | `same_sentence` | One sentence (8+ words) in 2+ sections (Export `repeats`) | each place | `h(sentence)` |
| 3 | `same_sentence_here` | One sentence twice in one section | 2nd place | `section|h(sentence)` |
| 3 | `same_paragraph` | One paragraph in 2+ places; its sentences are not listed again | each place | `h(paragraph)` |
| 3 | `overused_word` | A content word (4+ letters, not a common word, not in the book or chapter titles) used 20+ times and 25+ times per 10,000 words; at most 5 words (Q5) | first use in the section with most uses | `word` |
| 4 | `chapter_missing` | "Chapter N" when N is 0 or above the outline's chapter count (D6) | match | `section|h(sentence)` |
| 4 | `section_number` | "Section 2.3": the book has no section numbers (06 rule stays) | match | `section|h(sentence)` |
| 4 | `preview` | "next chapter", "later in this book" (06 rule stays) | sentence | `section|h(sentence)` |
| 4 | `leftover` | `[TODO]`, `TODO:`, `TBD`, `XXX`, `[insert …]`, `{{…}}`, `[citation needed]`, `lorem ipsum` | match | `section|h(match)` |

## 9. Edge cases

- No chapters, no sections, or no text anywhere → 55 C; no run saved; Next works.
- Only the Introduction has text → free checks run; promise button off: "No chapter has text yet."
- Sections renamed, moved or removed after a run → Out of date; removed ones show "Removed section", no link.
- Text changed in another tab during a run → `qc_stale`, nothing saved.
- Unsaved drafts or a Generate run in progress → QC reads saved text and says so; the promise
  check refuses a chapter with a fresh run.
- A chapter with no Final text is left out of the 08 PDF and later chapter numbers move up;
  QC uses the outline numbers and lists those sections in group 1 (§10, R5).
- 08 chapter label "None" → "Chapter 3" still points to a real chapter; not flagged (Q11).
- A spot edited after the run → the quote is searched; not found → "This spot changed."
- Very long sentences and paragraphs → hashed keys (≤ 300 characters).
- Results over the caps → "and N more" per group.
- Two tabs: Mark as OK twice → 23505 = done; Undo of a gone row = done.
- Promise: chapter under 50 or over 6,000 words → skipped with the reason; AI quote not found
  → no spot, Open in 06 opens the chapter's first section with text; Stop, closed tab or lost
  connection mid-chapter → the server finishes and saves; the next `qc_json` read shows it.
- Positioning unlocked after a promise check → every chapter Out of date (new `locked_at`).
- Completed book (0026) → QC works as usual; it never changes the status.
