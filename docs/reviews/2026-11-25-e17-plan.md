## A. Data model: recommend (2) new part tables
Option (1), new `chapters.kind` values, breaks or miscounts:
- 0016: kind is fixed, 30-chapter cap, positions (intro 0, conclusion n+1) rewritten by reorder; `replace_outline` deletes non-chapter rows; `outline_json` lists them in 05.
- 0017: adding a chapter/section clears outline approval → creating a part un-approves 05.
- 0026: `complete_book` needs every section Final (a Draft part blocks it); `book_reopen_on_change` reopens a completed book when a part row is added; `words_month` sums every section.
- 0010/0017 unlock: every section gets "Needs review" (parts would too).
- 0020/0021/0022/0024/0028: Generate, checks, kept findings and QC read every section (parts would get AI checks and chapter numbers).
- 0025 `export_badges`, 0027 `pdf_sections`, `js/export-rules.js` `partOn`: filter by kind, so parts drop silently but the word bar on the Books card and 06 totals would count them.
Option (2) changes none of these: they keep reading chapters/sections only. Parts never touch the word target by construction.

New tables (all: RLS on, `user_id default auth.uid()`, select/insert/update own rows on own book, no delete/truncate for anon/authenticated, `revoke all … from anon`):
1. `book_parts`: `book_id, kind, enabled bool default false, status 'draft'|'final' (null for review_request, also_by), current_version_id, created_at, updated_at`, unique `(book_id, kind)`. kind ∈ the 8 kinds. One row per kind per book, created by an after-insert trigger on `books` + backfill. Guard (every role, service role bypasses RLS): book_id/user_id/kind fixed; user = book owner; `current_version_id` changes only inside the RPCs (tx-local setting, as 0018) and only to a version of this part; status only on text kinds.
2. `book_part_versions`: insert-only, as `section_versions` (0018): `part_id, version_no, content ≤ 20,000 chars (epigraph ≤ 1,000, Q-8), word_count (md_word_count), source ∈ manual|restore|bio_copy|6 improve actions, label, partial`. Guard: insert only via the RPC setting; never for review_request/also_by.
3. `book_part_drafts`: autosave, one row per part, same rules as `section_drafts`.
4. `book_also_by`: `book_id, position, other_book_id (FK books on delete cascade) | title + subtitle (typed)`; check exactly one of the two; unique `(book_id, other_book_id)`; max 20 per book. Written only through `set_also_by(book, entries jsonb)` (whole list, atomic order). Tick rule as the 0027 guard: other book of same user, same pen name, not itself. Read rule as `also_by_valid`: a pen-name change drops ticks at read time.
5. `part_suggestions` + `apply_part_suggestion()`: mirror of 0021 for Improve (epigraph refused by the guard). The generate stage itself is Plan 2 (Q-9).

RPCs (SECURITY INVOKER, part row locked, no limit/budget inputs; caps are constants inside):
`save_part_version(part, content, base, make_current)`, `restore_part_version(part, version, base)`,
`copy_bio_to_about(book, base)`: saves unsaved draft text as a manual version first, then a `bio_copy` version from `pen_names.bio_text`. First open of About with no version calls the same RPC.
`book_parts_json(book)`: one read for 06, 07 and 08 (kind, enabled, status, words, version id, has_draft, Also by list with "valid").
Plain RLS updates: `enabled` and `status`. Delete paths: book delete cascades everything; pen name delete is already `restrict`; a ticked book's delete removes its Also by row (cascade). Grants: execute revoked from public, anon; granted to authenticated; trigger functions revoked from all.
