## 6. KDP risks still open (your Previewer run answers them)

1. **R10, flattened patches:** KDP has never seen a cover made of vector text over opaque 300 DPI JPEG patches. The files
   pass every check we know (one ICC sRGB profile shared by the vector colors and every JPEG, no transparency, no soft
   mask, fonts embedded as subsets). C-S1, C-S2 and C-L05 answer it.
2. **R10, the two JPEG kinds:** Chrome's patches carry an ICC v4 "sRGB" inside the JPEG stream, Safari's carry none. In
   both, the PDF still has exactly one ICCBased profile (Typst's). The C- and S- pairs answer it.
3. **Patch seams:** a patch's JPEG background next to the vector background differs by 0 to 2 levels of 255 (median).
   Invisible on screen; print is coarser than that. The Previewer shows it if KDP renders it differently.
4. **iPad Safari (not measured, no device):** iOS caps one canvas at 16.7 MP. The largest full image (19.6 MP) would fail
   there as a JPG (the PNG writer and the split patches would not). The editor needs 900 px or more, so this is iPad only.
5. **F5 font sizes** are a speed risk, not a KDP one.
