## Item 1 · stock v3: a header wait under 2 s counts as no header
**Today** (`supabase/functions/stock/handler.ts:178-182`, `withRetry`):
```
headerS = L.retryAfterSeconds(headers, now)              // "0" → 0
wait    = headerS !== null ? max(headerS*1000, MIN_WAIT_MS) : L.backoffMs(n, rand)
Stop(…, L.busyRetryAfter(headerS))                       // 0 → 1
```
**v3** (`lib.ts`, next to `retryAfterSeconds` at `:478`):
- `export const HEADER_MIN_S = 2;`
- `export function usableWait(s: number | null): number | null`. It returns `s >= HEADER_MIN_S ? s : null`, so null, 0, 1 and 1.99 all give null. `retryAfterSeconds` itself stays a pure header reader.
- `handler.ts`:
  - `raw = retryAfterSeconds(...)`, then `headerS = L.usableWait(raw)`;
  - `wait = headerS !== null ? headerS * 1000 : L.backoffMs(n, rand)`;
  - `busyRetryAfter(headerS)`.
- With a 0 or 1 header, the waits are 1.5 to 2.5 s, then 4 to 6 s, and `retry_after_s: 20` when the retries run out.
- **The log line keeps the raw value**: `failLine(..., raw)` still prints `retry-after 0`, so the logs show what Pixabay sent.
- `MIN_WAIT_MS` is no longer reachable (every header wait is now 2 s or more), so it is removed.
- `index.ts` header comment: "stock v3, E16.3". **User-Agent:** I propose `NicheInk-stock/3`, so the logs show which version sent a request (Q1).
- Unchanged: 2 retries per pick (shared), the 20 s wait budget, the 45 s deadline, the statuses retried, release on busy, everything else.

**Tests (Deno, `lib.test.ts`, `handler.test.ts`):**
- `usableWait`: null → null; 0, 1, 1.99 → null; 2 → 2; 41 → 41.
- Handler, each with a fake clock and fixed rand:
  - `Retry-After: "0"` on every try: waits 1.5–2.5 s then 4–6 s, then `stock_busy` with `retry_after_s: 20`; the log lines say `retry-after 0`;
  - `X-RateLimit-Reset: "0"`: the same;
  - `Retry-After: "1"`: the same;
  - `Retry-After: "2"`: waits 2 s and 2 s, then `retry_after_s: 2`;
  - `Retry-After: "0"` once, then 200: one backoff wait of 1.5 s or more, the picture stored.
- Changed: the 2 existing tests that use `"retry-after": "1"` (`handler.test.ts:577`, `:616`) now expect the backoff wait. The User-Agent checks at `:157`, `:281-282` change if Q1 says /3.
- Expected: stock Deno 141 → about 148 / 0.
