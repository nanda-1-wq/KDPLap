## 2. The 4 server checks (`lib/stages.ts`, the `partImprove` entry from line 403)

All run in `check()`, before the limits and before any AI call. A refusal writes no `ai_usage` row.

1. **The part belongs to the signed-in user's book.** `index.ts:410` `getPartContext` reads the book and the part
   through RLS as the caller, the part filtered by both `id` and `book_id` (`index.ts:413`). Someone else's book or
   part reads as null → the handler returns 404 `not_found`. `stages.ts:408` checks again that the row's `id` and
   `book_id` match the request → 404 `not_found`.
2. **A text kind.** `stages.ts:410`: `review_request` or `also_by` → 422 `part_no_improve`.
3. **Not the epigraph.** `stages.ts:412`: `epigraph`, or any kind outside `PART_IMPROVE_KINDS` → 422 `part_no_improve`.
   The 0035 guard refuses the same three kinds on insert (parity test).
4. **The base is the current version.** `stages.ts:416`: the request's `baseVersionId` must equal the part's
   `current_version_id` and the version read → 409 `version_conflict`, the same code and status section_improve gives.

Also, as sections: positioning locked (`stages.ts:414`, 409), 3 to 1,500 words (Expand 1,000), and the passage in the
draft or current version (`selection_not_in_text`).

**No limit in the request.** `parseInput` takes exactly the stage's keys (`limits.ts:424`), so `maxTokens`, `limit`,
`budget`, `reserve` and the rest are 400 `bad_request`. max_tokens comes from `improveMaxTokens(…, "part_improve")`
capped by `MAX_TOKENS.part_improve`; the reserve and the monthly limit are the server's (`limitError`).

**Context** = the Brief (topic, reader, problem), the pen name and its voice (picked in the Brief), and the locked
Positioning. No chapter text, no outline, no Research text in the prompt (tested).

**Usage log**: the handler's own step 6 (`handler.ts:162`), stage `part_improve`, exactly as section_improve:
success counted; "no changes" counted; AI errors, a failed save, and an About drop not counted.

## 3. The About drop rule

Prompt (`part_improve.ts:73`, About only): keep only the facts already in the passage, before or after; never add a
degree, job, title, award, number, year, place, name, employer, client, book or credential; never make a fact bigger.

Code (`aboutNewFacts`, `part_improve.ts:137`): the input is what the AI saw of the author (passage, before, after,
pen name). A new **number** (digits, not figures of speech such as 24/7; or a number word two to billion, dozen) or a
new **name** (a capitalized word not at a sentence start, and acronyms such as MBA or PhD anywhere) drops the
suggestion: nothing is saved, the reply is 502 `ai_new_facts`, the usage row is `failed`, not counted, and one log
line holds only counts, never the text:
`generate: part_improve dropped a suggestion (about_author): 0 new numbers, 2 new names`.
The other parts keep the section rule: a new name is a note, never a drop.

Two example tests (`lib.part_improve.test.ts`):
- **Example 1, planted names**: "She has taught for 12 years and holds a PhD from Stanford." → names `PhD`, `Stanford`
  (dropped). "MBA in hand, she opened a studio." → `MBA`. "I think Nora Hale is kind…" → nothing (pen name known).
- **Example 2, planted numbers**: "taught for 15 years" (the text says 12) → `15`; "Since 2014…" → `2014`;
  "twenty years… a dozen students" → `twenty`, `dozen`. "12 years, one class at a time, 24/7" → nothing.

End to end (`handler.part_improve.test.ts`): the PhD and Stanford reply gives 502, no save, a not counted row, and the
log line above. A changed number, a number word and "500 students" are each dropped. The same facts reworded are
kept and counted. The same "Stanford" reply on a foreword is kept, with Stanford as a note.

## 6. Choices I made myself (please confirm)

- **A. Two new codes.** `part_no_improve` (422) for checks 2 and 3, the same name as the 0035 guard. `ai_new_facts`
  (502) for an About drop. The drop is "stopped by the server", so it is not counted (§5).
- **B. Positioning lock required**, as sections (409 `positioning_not_locked`). Not in your list of 4, but the prompt
  sends the Positioning as locked.
- **C. The pen name and its voice are in the prompt.** Both come from the Brief (01 picks the pen name). The book
  title is not sent.
- **D. Number sources.** Research is read (never sent) only so a sourced number gets no "Verify: no source" mark, as
  sections. On About, the author's own text also counts as a source, so "12 years" gets no mark.
- **E. One known gap (question).** A single new name at the very start of a sentence ("Harvard trained her.") is
  not caught by code, only by the prompt. Catching every new sentence-start word would also drop good Expand
  replies ("Gentle movement became…"). Two capitalized words ("Harvard Medical"), mid-sentence names and acronyms
  are caught. Keep this, or drop on any new sentence-start word too (stricter, more retries)?
- **F. Number words**: two to twenty, the tens, hundred, thousand, million, billion, dozen. Not "one" (too common).
- **G. Base null** is allowed when the part has only a draft (as sections); Accept saves a version first (Part 4).
- **H. A turned-off part** can still be improved through the API (the UI never shows it). Not checked; not asked.
- **I. Prompt Fit rule for parts**: stay on the part's purpose, no new teaching or steps, keep the passage's point of
  view (About in the third person stays third person, even when the voice says "you"), and "section" in the shared
  task lines means this part. The six task lines are reused unchanged.
- **J. Settings usage name** "Improve book part" (UI text; rename if you prefer).
- **K. No new snapshot file** (snapshot.test.ts needs --allow-write to create one). The section prompt is checked
  equal to the shared builder in a test, and was byte-identical to 6525bd6 when I checked by hand.
